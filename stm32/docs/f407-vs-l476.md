# STM32F407 → STM32L476RG translation notes

The FastBit courses (MCU1 *Mastering Microcontroller with Peripheral Driver Development*,
and MCU2 / DMA / RTOS / bootloader after it) are filmed on an **STM32F407 Discovery**. The
bench board is the **Nucleo-L476RG**. Same Cortex-M4F core, different ST silicon around it:
when the instructor types an address, an offset or a bit, translate it here, then confirm in
RM0351. The processor-course subset lives in
[../embedded-system-programming-on-arm-cortex-m3m4/SYLLABUS.md](../embedded-system-programming-on-arm-cortex-m3m4/SYLLABUS.md).

Sources: the ST SVD files in `/opt/st/stm32cubeclt_1.22.0/STMicroelectronics_CMSIS_SVD/`,
CubeProgrammer's device databases (`STM32CubeProgrammer/Data_Base/STM32_Prog_DB_0x413.xml`
= F405/F407, `0x415` = L476), and [RM0351](RM0351_stm32l476_reference_manual.pdf). The
F407's own manual is RM0090 (not in this folder).

## Which source to trust

- **Reference manual** — the authority for addresses, offsets, bits, reset values.
- **Datasheet** — the authority for which peripherals a part *has*.
- **SVD / CMSIS header** — convenient copies of the manual, with errors:
  - The F405 SVD lists Ethernet and DCMI; the F405 has neither (F407 does). The L476 SVD
    lists DCMI; only the L49x has it. ST shares one SVD across a family.
  - L476 SVD: GPIOA `MODER` reset = `0xA800_0000`. RM0351: `0xABFF_FFFF`.
  - L476 SVD: SPI `CR1` bit 11 = `DFF`. RM0351: bit 11 is `CRCL` (data size moved to `CR2.DS`).

## Core — identical

NVIC, SCB (`0xE000_ED00`), SysTick, MPU, FPU, bit-banding, all exceptions: same addresses,
same behavior. Only the IRQ list past the 16 system exceptions differs (82 entries in the
F407 SVD, 83 in the L476) — take IRQ numbers from the chip's `IRQn_Type`, never the video.

## Memory

| | L476RG | F405/F407 |
|---|---|---|
| Flash | `0x0800_0000`, 1 MB, 2 KB pages, dual bank (bank 2 at `0x0808_0000`) | `0x0800_0000`, up to 1 MB, uneven sectors: 4×16 KB, 1×64 KB, then 128 KB |
| Main SRAM | `0x2000_0000`, 96 KB | `0x2000_0000`, 128 KB (112 + 16) |
| `0x1000_0000` | SRAM2, 32 KB — executes code, DMA-reachable | CCM RAM, 64 KB — CPU data only: no code, no DMA |
| OTP | `0x1FFF_7000` (1 KB) | `0x1FFF_7800` (528 B) |
| Option bytes | `0x1FFF_7800` / `0x1FFF_F800` | `0x1FFF_C000` |

Flash erase granularity matters for the bootloader course and for storing settings: 2 KB on
the L476, 16–128 KB on the F407.

## Peripheral base addresses

Same on both: USART2 `0x4000_4400`, TIM2 `0x4000_0000`, I2C1 `0x4000_5400`, SPI1
`0x4001_3000`, PWR `0x4000_7000`, IWDG, RTC, CRC `0x4002_3000`, RNG, OTG_FS.

| | L476 | F407 |
|---|---|---|
| GPIOA (B, C… +`0x400` each) | `0x4800_0000` (AHB2) | `0x4002_0000` (AHB1) |
| RCC | `0x4002_1000` | `0x4002_3800` |
| FLASH interface | `0x4002_2000` | `0x4002_3C00` |
| DMA1 / DMA2 | `0x4002_0000` / `0x4002_0400` | `0x4002_6000` / `0x4002_6400` |
| USART1 | `0x4001_3800` | `0x4001_1000` |
| TIM1 | `0x4001_2C00` | `0x4001_0000` |
| SYSCFG / EXTI | `0x4001_0000` / `0x4001_0400` | `0x4001_3800` / `0x4001_3C00` |
| ADC1 | `0x5004_0000` (AHB2) | `0x4001_2000` (APB2) |

## RCC clock enables

Bit positions mostly match; register offsets don't.

| Enable | L476 | F407 |
|---|---|---|
| GPIO ports | `AHB2ENR` @ `0x4C`, GPIOA = bit 0 | `AHB1ENR` @ `0x30`, GPIOA = bit 0 |
| USART2 / I2C1 | `APB1ENR1` @ `0x58`, bits 17 / 21 | `APB1ENR` @ `0x40`, bits 17 / 21 |
| SPI1 | `APB2ENR` @ `0x60`, bit 12 | `APB2ENR` @ `0x44`, bit 12 |
| SYSCFG | `APB2ENR` bit **0** | `APB2ENR` bit **14** |

## Register models, per driver section of MCU1

| Peripheral | Verdict | What changes on the L476 |
|---|---|---|
| RCC clock output (MCO) | Same pin, different fields | PA8 AF0 on both. F407: `CFGR.MCO1[22:21]` resets to `00` = HSI and the chip boots on HSI, so the pin setup alone outputs 16 MHz; prescaler `MCO1PRE[26:24]`, ÷4 = `110`. L476: `MCOSEL[27:24]` resets to `0000` = **off**, and HSI is off at reset — set `CR.HSION`, wait `HSIRDY`, set `MCOPRE[30:28]` (÷4 = `010`) before `MCOSEL = 0011`. Reference: `mastering-microcontroller-with-peripheral-driver-development/exercises/hsi-measurement/` |
| GPIO | Same layout | Adds `BRR` @ `0x28`, `ASCR` @ `0x2C`. Pins reset to **analog** (`11`), not input — clear the `MODER` field before setting it; `\|= 1` alone leaves `11` |
| EXTI / SYSCFG | Same offsets | `EXTICR1..4` @ `0x08..0x14` and `IMR1..PR1` @ `0x00..0x14` match; L4 adds a second EXTI bank (`IMR2…` @ `0x20+`); SYSCFG enable bit differs (above) |
| SPI | Same names, newer IP | 4–16-bit frames via `CR2.DS[3:0]` (F4: `CR1.DFF`, 8/16 only); RX FIFO with `CR2.FRXTH`. An 8-bit frame needs an **8-bit** `DR` access — a 16-bit write packs two frames (RM0351 "Data packing") |
| USART | Different IP | F4 `SR`/`DR`; L4 `ISR`/`ICR`/`RDR`/`TDR`, every offset shuffled (`CR1` @ `0x00`, `BRR` @ `0x0C`). Reference: `Src/uart2.c` |
| I2C | Different IP | F4's `SR1`/`SR2` event dance + `CCR`/`TRISE` doesn't exist. L4: `TIMINGR`, `CR2` with `NBYTES`/`START`/`AUTOEND`, `ISR`/`ICR`, `RXDR`/`TXDR`. Write the driver from RM0351, not the video. Reference: `embedded-system-programming-on-arm-cortex-m3m4/Src/i2c3.c` |

## Board

| Course assumes (F407 Discovery) | Nucleo-L476RG |
|---|---|
| 16 MHz HSI at boot | 4 MHz MSI — recompute every baud rate (`BRR`), I2C timing, delay count |
| LEDs PD12–PD15 | LD2 on PA5 only |
| User button PA0, reads 1 when pressed | B1 on PC13, reads 0 when pressed |

## Translating one instructor line

1. Name the peripheral and register (`GPIOD->ODR`, `RCC_AHB1ENR`).
2. RM0351 §2.2.2 Table 1 for the base; the peripheral's register-map section for offset and bits.
3. Check the IP version: GPIO/EXTI translate by address, SPI mostly, USART/I2C need a rewrite.
